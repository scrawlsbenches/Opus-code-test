## Algorithm
**Name:** Trie for Comment Marker Lookup
**Expected complexity:** O(m) insert/search where m = key length
**Required operations:**
- `insert(marker: str)` - Add a comment marker to the trie
- `search(marker: str) -> bool` - Check if exact marker exists
- `starts_with(prefix: str) -> bool` - Check if any marker starts with prefix
- `get_all_with_prefix(prefix: str) -> List[str]` - Get all markers with prefix
- `delete(marker: str) -> bool` - Remove a marker

## Codebase Application

**Problem:** The Cortical codebase uses many comment markers:
- `FUTURE:` - Speculative promises (often misleading)
- `TODO:` - Actionable work items
- `FIXME:` - Known bugs to fix
- `See:` - References to other files (may not exist)
- `NOTE:` - Important information
- `WARNING:` - Caution notes
- `HACK:` - Technical debt markers

A Trie enables:
1. Fast prefix matching for all `FI*` markers (FIXME, Fix, etc.)
2. Autocomplete for comment marker suggestions
3. Grouping markers by category (all `F*` vs all `T*`)

**Use Case:** When scanning comments, quickly identify marker types by prefix.

**Reference:** Comment scanning happens in audit processing. See `docs/audits/` for finding patterns.
