## Algorithm
**Name:** Locality Sensitive Hashing for Similar Comment Detection
**Expected complexity:** O(k) per document hashing, O(1) candidate lookup, sub-linear search
**Required operations:**
- `add(comment_id: str, tokens: Set[str])` - Add comment to index
- `query(tokens: Set[str], threshold: float) -> List[str]` - Find similar comments
- `minhash_signature(tokens: Set[str]) -> Tuple` - Get MinHash signature

## Codebase Application

**Problem:** We need to find comments that are similar to known misleading ones:
- A new comment "FUTURE: When feature X is done, this will be implemented" is similar to existing misleading comment "FUTURE: When CDG index is done, this will be handled"
- We want to flag comments that are semantically similar to known bad patterns

LSH with MinHash enables fast approximate nearest neighbor search based on Jaccard similarity of word sets.

**Use Case:** Given a new comment, find existing comments with similar word sets (potential copy-paste variations).

**Reference:** This complements the Naive Bayes experiment (which uses word probabilities) by using set similarity.

Key insight for MinHash:
    If you pick a random hash function h, then:
    P(min(h(A)) == min(h(B))) = J(A, B) = |A ∩ B| / |A ∪ B|

Key insight for banding:
    Divide signature into b bands of r rows each.
    Two docs are candidates if they match in at least one band.
    P(candidate) ≈ 1 - (1 - s^r)^b where s = true similarity

## Analysis
**Discrepancy:** Same as predicted - got PARTIAL due to LSH complexity
**Root cause:** LSH is fundamentally probabilistic. With similarity s=0.54, r=5 rows/band, b=20 bands: P(candidate) ≈ 1-(1-s^r)^b ≈ 60.9%. Test 8 fell into the 39.1% miss probability. This is EXPECTED behavior for approximate nearest neighbor search.
**Learning:** LSH trades recall for speed. The probability that two documents with similarity s are found as candidates is 1-(1-s^r)^b. Higher similarity → higher recall probability. More bands → higher recall but slower. MinHash property: P(min(h(A))==min(h(B))) = Jaccard(A,B). Banding reduces O(n²) all-pairs comparisons to sub-linear candidate generation.
