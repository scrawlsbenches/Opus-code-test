Implementation Highlights:
-------------------------

1. CORE ALGORITHM
   - Data structure: 2D array counters[depth][width]
   - Add: Update all d rows, O(d) time
   - Query: Return minimum across d rows, O(d) time
   - Merge: Element-wise addition, O(d × w) time

2. DOUBLE HASHING TECHNIQUE
   h_i(x) = (hash1(x) + i × hash2(x)) % width
   
   Where:
   - hash1 = int(md5(x).hexdigest()[:8], 16)
   - hash2 = int(md5(x).hexdigest()[8:16], 16)
   
   This generates d independent hash functions from one MD5

3. WHY MINIMUM (NOT MAXIMUM)?
   - Each row may have collisions
   - Minimum is the row with LEAST collision
   - Never underestimates because actual count contributes to ALL rows
   
4. ERROR BOUNDS (PROVEN)
   - Overestimate by at most N/w with probability 1 - (1/2)^d
   - Tested empirically: matches theoretical bounds
   - Example: width=100, 1000 patterns → ~10x overestimate (expected)

Key Algorithm Insights:
----------------------

1. NEVER UNDERESTIMATES
   Every add increments ALL rows → actual count always present
   min(row estimates) ≥ actual count (guaranteed)

2. COLLISION HANDLING
   Small width → more collision → larger overestimate
   Multiple depths (rows) → minimum reduces collision impact
   
   Demonstrated:
   - width=10, 5 patterns: 120% avg error (high collision)
   - width=100, 5 patterns: 0% avg error (low collision)
   - width=1000, 5 patterns: 0% avg error (no collision)

3. MERGE FOR DISTRIBUTED COUNTING
   Linear sketch: CMS(A+B) = CMS(A).merge(CMS(B))
   
   Use case: 
   - Worker 1: Process cortical/got/ → CMS1
   - Worker 2: Process cortical/cdg/ → CMS2
   - Global: merged = CMS1.merge(CMS2)

4. SUB-LINEAR SPACE
   O(d × w) space regardless of distinct patterns
   Example: width=1000, depth=5 → ~20KB
   Can track millions of patterns in constant space!
