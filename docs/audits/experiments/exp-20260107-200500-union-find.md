## Algorithm
**Name:** Union-Find for Audit Finding Clustering
**Expected complexity:** O(α(n)) per operation with path compression and union by rank
**Required operations:**
- `make_set(finding_id)` - Create a set for a finding
- `find(finding_id) -> root` - Find the cluster representative
- `union(f1, f2)` - Merge two findings into same cluster
- `connected(f1, f2) -> bool` - Check if findings are in same cluster
- `get_clusters() -> List[Set[str]]` - Get all clusters

## Codebase Application

**Problem:** We have 29 audit findings. Some are related (e.g., two comments referencing the same non-existent file). We want to cluster related findings.

**Use Case:**
- Group findings by pattern (all "See: missing-file" references)
- Track which findings were addressed together
- Find related issues when fixing one

**Reference:** This mirrors how GoT tracks related tasks via edges (see `cortical/got/indexer.py`).

Why path compression matters:
    Without it: find() is O(n) worst case (tall trees)
    With it: find() is O(α(n)) ≈ O(1) amortized

Why union by rank matters:
    Without it: tree becomes linked list after bad union sequence
    With it: tree depth is O(log n), combined with path compression gives O(α(n))
