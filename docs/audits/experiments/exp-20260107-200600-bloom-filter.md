## Algorithm
**Name:** Bloom Filter for Suspicious Comment Detection
**Expected complexity:** O(k) insert and query where k = number of hash functions
**Required operations:**
- `add(comment_hash: str)` - Add comment pattern to the filter
- `probably_suspicious(comment_hash: str) -> bool` - Check if pattern is probably suspicious
- `false_positive_rate() -> float` - Estimate current false positive rate

## Codebase Application

**Problem:** We want fast pre-screening of comments to check if they match known misleading patterns:
- "Probably suspicious" (may have false positives) → needs human review
- "Definitely not suspicious" (never has false negatives) → safe to skip

This is useful for:
1. Fast filtering of thousands of comments during code review
2. CI pipeline checks that flag potentially misleading comments
3. IDE plugins that warn about suspicious patterns

**Use Case:** Given a comment pattern hash, quickly check if it's in our set of known misleading patterns.

**Reference:** The audit framework in `docs/audits/` has 10 known misleading patterns we can use as our "suspicious" set.

## Hypothesis

**Because:** The bit array and multiple hashing is straightforward, but calculating optimal parameters requires understanding the math.
