Q: What is Big-O notation and why is it important for analyzing algorithms?
A: Big-O notation is a mathematical notation that describes the upper bound of an algorithm's time or space complexity as the input size grows toward infinity. It abstracts away constants and lower-order terms to focus on the dominant factor affecting performance. This notation is crucial because it allows developers to compare algorithms objectively and predict how they will scale with larger datasets. For example, an O(n log n) sorting algorithm will dramatically outperform an O(n^2) algorithm when processing millions of records.

Q: How does QuickSort work and what is its average-case time complexity?
A: QuickSort is a divide-and-conquer sorting algorithm that works by selecting a pivot element and partitioning the array so that elements smaller than the pivot are placed before it, and larger elements after it. The algorithm then recursively applies the same process to the sub-arrays on either side of the pivot. Its average-case time complexity is O(n log n), making it one of the fastest general-purpose sorting algorithms in practice. However, its worst-case complexity is O(n^2), which occurs when the pivot selection consistently results in highly unbalanced partitions, such as when the array is already sorted and the first element is always chosen as the pivot.

Q: What are the three main tree traversal methods and when would you use each?
A: The three main tree traversal methods are in-order, pre-order, and post-order traversal. In-order traversal visits the left subtree, then the root, then the right subtree, which produces nodes in sorted order for binary search trees and is ideal for operations requiring sorted data. Pre-order traversal visits the root first, then left and right subtrees, making it useful for creating a copy of the tree or serializing the tree structure. Post-order traversal visits both subtrees before the root, which is essential for operations like deleting a tree or evaluating expression trees where child nodes must be processed before their parents.

Q: What is Dijkstra's algorithm and what problem does it solve?
A: Dijkstra's algorithm is a graph algorithm that finds the shortest path from a source vertex to all other vertices in a weighted graph with non-negative edge weights. It works by maintaining a set of visited vertices and repeatedly selecting the unvisited vertex with the smallest known distance from the source, then updating the distances of its neighbors. The algorithm uses a greedy approach and typically employs a priority queue (min-heap) for efficient vertex selection, achieving a time complexity of O((V + E) log V) where V is vertices and E is edges. It is widely used in GPS navigation systems, network routing protocols, and any application requiring optimal pathfinding.

Q: What is dynamic programming and how does it differ from simple recursion?
A: Dynamic programming is an optimization technique that solves complex problems by breaking them down into simpler overlapping subproblems and storing the results of these subproblems to avoid redundant computation. Unlike simple recursion, which may solve the same subproblem multiple times leading to exponential time complexity, dynamic programming uses memoization (top-down) or tabulation (bottom-up) to ensure each subproblem is solved only once. This approach transforms problems like computing the nth Fibonacci number from O(2^n) with naive recursion to O(n) with dynamic programming. Dynamic programming is applicable when a problem exhibits both optimal substructure and overlapping subproblems.

Q: How do hash tables achieve O(1) average-case lookup time?
A: Hash tables achieve O(1) average-case lookup time by using a hash function to compute an index directly from a key, allowing immediate access to the corresponding value in an underlying array. The hash function transforms the key into an integer that maps to a specific bucket or slot in the table. When collisions occur (multiple keys mapping to the same index), techniques like chaining (linked lists at each bucket) or open addressing (probing for the next available slot) are used to handle them. The O(1) performance relies on a good hash function that distributes keys uniformly and maintaining a reasonable load factor, typically below 0.75, to minimize collision frequency.

Q: What is a heap data structure and what are its primary use cases?
A: A heap is a complete binary tree that satisfies the heap property: in a max-heap, every parent node is greater than or equal to its children, while in a min-heap, every parent is less than or equal to its children. Heaps are typically implemented as arrays where for any element at index i, its children are at indices 2i+1 and 2i+2, and its parent is at (i-1)/2. The primary use cases include implementing priority queues with O(log n) insertion and extraction of the min/max element, heap sort algorithm, and efficient algorithms like Dijkstra's shortest path and Prim's minimum spanning tree. Heaps provide an elegant balance between the simplicity of arrays and the ordering guarantees needed for priority-based operations.

Q: What is a trie and when is it more efficient than a hash table for string operations?
A: A trie (prefix tree) is a tree-like data structure where each node represents a character, and paths from root to nodes represent prefixes of stored strings. Tries excel at prefix-based operations such as autocomplete, spell checking, and IP routing table lookups, where you need to find all strings sharing a common prefix in O(m) time where m is the prefix length. Unlike hash tables, which require O(n) time to find all strings with a given prefix, tries naturally group strings by their prefixes. Tries also provide lexicographic ordering of keys and never have hash collisions, though they may use more memory than hash tables for small datasets with long keys that share few common prefixes.

Q: How does binary search work and what are its requirements?
A: Binary search is an efficient algorithm for finding a target value in a sorted array by repeatedly dividing the search interval in half. It compares the target with the middle element: if they match, the search succeeds; if the target is smaller, it searches the left half; if larger, the right half. This process continues until the element is found or the interval becomes empty. The key requirement is that the array must be sorted, and the algorithm achieves O(log n) time complexity, making it vastly more efficient than linear search for large datasets. Binary search is fundamental to many applications including database indexing, dictionary lookups, and as a subroutine in more complex algorithms like finding the square root or detecting duplicates.

Q: What are the tradeoffs between recursion and iteration?
A: Recursion provides elegant, readable solutions for problems with natural recursive structure like tree traversals, divide-and-conquer algorithms, and mathematical sequences, but it incurs function call overhead and risks stack overflow for deep recursion. Iteration uses explicit loops and typically consumes less memory since it doesn't build up a call stack, making it more suitable for performance-critical code and problems with straightforward linear progression. Many recursive algorithms can be converted to iterative versions using explicit stacks, which provides the logical clarity of recursion with the memory efficiency of iteration. The choice often depends on the problem domain, language support for tail-call optimization, and whether code clarity or raw performance is the priority.

Q: What is the difference between BFS and DFS graph traversal algorithms?
A: Breadth-First Search (BFS) explores all neighbors at the current depth before moving to nodes at the next depth level, using a queue data structure to maintain the frontier of nodes to visit. Depth-First Search (DFS) explores as far as possible along each branch before backtracking, using either recursion or an explicit stack. BFS is optimal for finding the shortest path in unweighted graphs and is used in algorithms like finding connected components and level-order traversal, while DFS is preferred for topological sorting, cycle detection, and maze solving. BFS has O(V+E) time complexity but may use O(V) space for the queue in wide graphs, whereas DFS uses O(V) space for the recursion stack in deep graphs.

Q: What is amortized analysis and how does it apply to dynamic arrays?
A: Amortized analysis is a technique for analyzing the average time complexity of operations over a sequence of operations, rather than the worst-case of individual operations. Dynamic arrays exemplify this: when an array reaches capacity, a costly O(n) resize operation copies all elements to a new, larger array (typically doubling the size). While this single operation is expensive, it happens infrequently enough that when costs are amortized over all insertions, each append operation averages O(1) time. This is because after doubling from size n to 2n, the array can accommodate n more insertions before the next resize. Amortized analysis provides a more realistic picture of data structure performance in practice than worst-case analysis alone.

Q: How does merge sort guarantee O(n log n) performance regardless of input?
A: Merge sort is a divide-and-conquer algorithm that recursively divides the array into two halves until single elements remain, then merges the sorted halves back together in order. The key insight is that merging two sorted arrays of size n/2 takes O(n) time, and the recursion creates log n levels of division. At each level, the total work across all merge operations is O(n), giving the overall O(n log n) complexity. Unlike QuickSort, merge sort's performance doesn't depend on pivot selection or input distribution, making it stable and predictable. The tradeoff is that merge sort requires O(n) additional space for the merge operation, whereas in-place variants exist but are more complex to implement.

Q: What is a balanced binary search tree and why is balance important?
A: A balanced binary search tree (BST) is a BST where the heights of the left and right subtrees of every node differ by at most a constant factor, ensuring the tree height remains O(log n) where n is the number of nodes. Without balancing, a BST can degenerate into a linked list when elements are inserted in sorted order, resulting in O(n) search, insertion, and deletion times. Self-balancing trees like AVL trees, Red-Black trees, and B-trees automatically perform rotations or restructuring during insertions and deletions to maintain balance. This guarantees O(log n) operations for all cases, making balanced BSTs essential for database indices, in-memory ordered maps, and any application requiring consistent performance with ordered data.

Q: What is the two-pointer technique and when is it applicable?
A: The two-pointer technique uses two indices or references that traverse a data structure, typically an array, simultaneously to solve problems more efficiently than nested loops. Common patterns include pointers moving toward each other from opposite ends (useful for palindrome checking or finding pairs that sum to a target in a sorted array), or a fast and slow pointer (used for cycle detection in linked lists or finding the middle element). This technique often reduces O(n^2) brute-force solutions to O(n) time complexity while using O(1) extra space. It is applicable when the problem involves searching for pairs or subarrays in sorted data, partitioning arrays, or detecting patterns in sequences where the relationship between elements at different positions matters.
