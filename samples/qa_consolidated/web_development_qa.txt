Q: What is the Document Object Model (DOM) and how does JavaScript interact with it?
A: The Document Object Model (DOM) is a programming interface that represents HTML and XML documents as a tree structure of nodes, where each element, attribute, and piece of text becomes an object that can be manipulated. JavaScript interacts with the DOM through methods like getElementById, querySelector, and querySelectorAll to select elements, and properties like innerHTML, textContent, and classList to modify content and styling. When JavaScript modifies the DOM, the browser re-renders the affected portions of the page, making it possible to create dynamic, interactive web applications without full page reloads. Understanding DOM manipulation is fundamental to frontend development, though modern frameworks often abstract direct DOM access through virtual DOM implementations.

Q: How does CSS Flexbox differ from CSS Grid, and when should you use each?
A: CSS Flexbox is a one-dimensional layout system designed for distributing space along a single axis (either row or column), making it ideal for navigation menus, card layouts within a row, and centering content. CSS Grid is a two-dimensional layout system that handles both rows and columns simultaneously, excelling at creating complex page layouts, dashboard designs, and any structure requiring precise control over both axes. Use Flexbox when you need to align items in a single direction and want the layout to adapt based on content size, while Grid is preferable when you need to define explicit track sizes and place items in specific grid cells. Many modern layouts combine both: Grid for the overall page structure and Flexbox for component-level alignment within grid areas.

Q: What is event bubbling in JavaScript and how can you control it?
A: Event bubbling is the DOM event propagation mechanism where an event triggered on a nested element propagates upward through its ancestor elements, firing handlers on each parent until reaching the document root. For example, clicking a button inside a div will trigger click handlers on the button first, then the div, then any parent containers. You can control bubbling using event.stopPropagation() to prevent the event from reaching parent elements, or event.stopImmediatePropagation() to also prevent other handlers on the same element from executing. Event delegation leverages bubbling by attaching a single handler to a parent element to manage events for multiple children, improving performance and handling dynamically added elements.

Q: Explain the difference between async/await and Promises in JavaScript.
A: Promises and async/await both handle asynchronous operations, but async/await provides syntactic sugar that makes asynchronous code read like synchronous code. A Promise represents a value that may be available now, later, or never, with .then() for success and .catch() for errors, often leading to chained callbacks that can be difficult to follow. Async/await allows you to write const result = await somePromise instead of promise.then(result => ...), making the code flow linearly and error handling possible with standard try/catch blocks. Under the hood, async functions always return Promises and await pauses execution within the async function until the Promise resolves, so they are interoperable and choosing between them is largely a matter of readability and coding style.

Q: What are media queries and how do they enable responsive design?
A: Media queries are CSS conditional rules that apply styles only when certain conditions about the viewing environment are met, most commonly the viewport width. They use the @media syntax followed by conditions like (min-width: 768px) or (max-width: 1024px) to target specific screen sizes, enabling different layouts for mobile, tablet, and desktop devices. A mobile-first approach starts with base styles for small screens and progressively adds complexity using min-width queries, while desktop-first does the reverse with max-width queries. Modern responsive design combines media queries with flexible units like percentages, em, rem, vw, and vh, along with Flexbox and Grid, to create layouts that adapt fluidly across all screen sizes.

Q: What is ARIA and why is it important for web accessibility?
A: ARIA (Accessible Rich Internet Applications) is a set of HTML attributes that enhance the semantic meaning of web content for assistive technologies like screen readers, particularly for dynamic content and custom UI components. When native HTML elements cannot convey the full meaning or state of an interface element, ARIA attributes like role, aria-label, aria-describedby, and aria-live provide the necessary context. For example, a custom dropdown built with divs needs role="listbox" and role="option" to communicate its purpose, while aria-expanded indicates whether it is open. However, the first rule of ARIA is to use native HTML elements whenever possible, as they have built-in accessibility support that ARIA cannot fully replicate.

Q: How does the JavaScript event loop work with the call stack and task queue?
A: The JavaScript event loop is the mechanism that enables asynchronous programming in the single-threaded JavaScript runtime by coordinating the call stack, callback queue (task queue), and microtask queue. When synchronous code executes, functions are pushed onto and popped off the call stack; when the stack empties, the event loop checks for pending callbacks in the queues. Microtasks (from Promises and queueMicrotask) have priority over macrotasks (from setTimeout, setInterval, DOM events), meaning all microtasks execute before the next macrotask begins. Understanding this model explains why console.log in a Promise.then() executes before a setTimeout with 0ms delay, and helps developers write non-blocking code that keeps the UI responsive.

Q: What is the purpose of the Intersection Observer API and how is it used?
A: The Intersection Observer API provides an efficient way to asynchronously observe changes in the intersection of a target element with an ancestor element or the viewport, replacing expensive scroll event listeners. Common use cases include lazy loading images when they enter the viewport, implementing infinite scroll, triggering animations when elements become visible, and tracking ad impressions. You create an observer with a callback function and options specifying the root element, margins, and threshold percentages, then call observer.observe(element) for each target. The callback receives entries describing which elements intersected and by how much, allowing you to respond without blocking the main thread or causing layout thrashing from repeated getBoundingClientRect calls.

Q: What is the virtual DOM and why do frameworks like React use it?
A: The virtual DOM is an in-memory representation of the actual DOM, stored as a lightweight JavaScript object tree that can be manipulated without directly touching the browser's DOM. When state changes in a React component, React creates a new virtual DOM tree, compares it with the previous one through a process called reconciliation or diffing, and calculates the minimal set of actual DOM operations needed. This batching and optimization reduces expensive DOM manipulations, which are slow because they can trigger style recalculation, layout, and repaint operations. The virtual DOM also enables declarative programming where developers describe what the UI should look like for a given state, and the framework handles the imperative DOM updates efficiently.

Q: How do CSS custom properties (variables) work and what advantages do they offer?
A: CSS custom properties, defined with a double-hyphen prefix like --primary-color: #3498db, store values that can be reused throughout a stylesheet using the var() function. Unlike preprocessor variables from Sass or Less, CSS custom properties are live in the browser, cascade through the DOM, can be scoped to specific selectors, and can be modified at runtime with JavaScript. They enable theming by defining variables at the :root level and overriding them for dark mode or different components, reducing repetition and making global changes trivial. Custom properties also work with the calc() function and can have fallback values with var(--color, blue), making stylesheets more maintainable and dynamic without build tools.

Q: What are Web Components and what technologies comprise them?
A: Web Components are a set of browser-native APIs that enable developers to create reusable, encapsulated custom HTML elements that work across frameworks and vanilla JavaScript. The three main technologies are Custom Elements for defining new HTML tags with associated JavaScript behavior, Shadow DOM for encapsulating styles and markup so they do not leak out or get affected by external styles, and HTML Templates for declaring markup fragments that remain inert until instantiated. You create a Web Component by extending HTMLElement, defining its behavior in lifecycle callbacks like connectedCallback and attributeChangedCallback, and registering it with customElements.define(). Web Components provide true interoperability since they are native browser features, making them ideal for design systems and shareable UI libraries.

Q: What is CORS and why do browsers enforce it?
A: Cross-Origin Resource Sharing (CORS) is a security mechanism that allows servers to specify which origins can access their resources, enforced by browsers to prevent malicious websites from making unauthorized requests to other domains. When JavaScript makes a fetch request to a different origin, the browser sends an Origin header and checks the response for Access-Control-Allow-Origin and related headers before allowing the script to access the response. For non-simple requests (those with custom headers, methods other than GET/POST/HEAD, or certain content types), browsers send a preflight OPTIONS request first to verify permissions. CORS protects users from cross-site request forgery attacks while enabling legitimate cross-origin communication when servers explicitly opt in.

Q: How does React's useEffect hook work and what are its dependency array rules?
A: The useEffect hook in React lets you perform side effects in functional components, such as data fetching, subscriptions, or manually changing the DOM, running after the component renders. The dependency array, the second argument, controls when the effect re-runs: an empty array means the effect runs only on mount and cleanup on unmount, while listing specific values causes re-runs when those values change. Omitting the dependency array entirely makes the effect run after every render, which is rarely desired and can cause performance issues or infinite loops. The effect function can return a cleanup function that runs before the component unmounts or before the effect re-runs, essential for canceling subscriptions, clearing timers, or aborting fetch requests to prevent memory leaks.

Q: What is the difference between localStorage, sessionStorage, and cookies?
A: localStorage and sessionStorage are Web Storage APIs that store key-value string pairs in the browser, while cookies are small text files sent with HTTP requests and managed by document.cookie or Set-Cookie headers. localStorage persists indefinitely until explicitly cleared and is shared across all tabs of the same origin, while sessionStorage is cleared when the tab closes and is isolated per tab. Cookies have a maximum size of about 4KB compared to 5-10MB for Web Storage, can have expiration dates, and are automatically sent with every HTTP request to the matching domain, making them suitable for authentication but adding network overhead. For pure client-side state that does not need server access, Web Storage is preferred; cookies remain necessary for server-side session management and scenarios requiring HTTP-only or secure flags for security.

Q: What is code splitting and how does it improve web application performance?
A: Code splitting is a technique that breaks a JavaScript bundle into smaller chunks that can be loaded on demand, reducing the initial payload and improving time-to-interactive for web applications. Instead of downloading one large bundle containing all application code, users download only the code needed for the current view, with additional chunks fetched when navigating to new routes or interacting with features. Modern bundlers like Webpack and frameworks like React support code splitting through dynamic import() syntax, which returns a Promise and creates a separate chunk at build time. Combined with React.lazy for component-level splitting and Suspense for loading states, this pattern is essential for large applications where loading all code upfront would create unacceptable delays, especially on slower networks or devices.
