Networking Fundamentals Q&A

Q: What is the difference between TCP and UDP, and when would you choose one over the other?
A: TCP (Transmission Control Protocol) is a connection-oriented protocol that guarantees reliable, ordered delivery of data through acknowledgments, retransmissions, and flow control. UDP (User Datagram Protocol) is connectionless and provides no delivery guarantees, making it faster but less reliable. You would choose TCP for applications requiring data integrity like file transfers, web browsing, and email, while UDP is preferred for real-time applications like video streaming, online gaming, and VoIP where speed matters more than occasional packet loss.

Q: How does DNS resolution work when you type a URL into your browser?
A: When you enter a URL, your browser first checks its local cache for a cached DNS record. If not found, it queries the operating system's DNS resolver, which checks its own cache before contacting a recursive DNS server (typically provided by your ISP). The recursive server queries root nameservers, then TLD nameservers (like .com), and finally the authoritative nameserver for the domain to obtain the IP address. This hierarchical lookup process typically takes milliseconds and the results are cached at multiple levels with TTL (Time To Live) values to reduce future lookup times.

Q: What is the TLS handshake process and why is it important for HTTPS?
A: The TLS handshake is a negotiation process that establishes a secure encrypted connection between a client and server. It begins with the client sending supported cipher suites and TLS versions, followed by the server responding with its certificate and chosen cipher suite. The client verifies the certificate against trusted Certificate Authorities, then both parties exchange key material to derive symmetric session keys. This process is crucial for HTTPS because it authenticates the server's identity, prevents man-in-the-middle attacks, and establishes the encryption keys used to protect all subsequent HTTP traffic.

Q: How do load balancers distribute traffic and what are the common load balancing algorithms?
A: Load balancers act as reverse proxies that distribute incoming network traffic across multiple backend servers to ensure no single server becomes overwhelmed. Common algorithms include Round Robin (requests distributed sequentially), Least Connections (traffic sent to the server with fewest active connections), IP Hash (consistent routing based on client IP), and Weighted distribution (servers receive traffic proportional to assigned weights). Advanced load balancers also perform health checks on backend servers, automatically removing unhealthy instances from the rotation and providing session persistence when needed.

Q: What is a CDN and how does it improve web application performance?
A: A Content Delivery Network (CDN) is a geographically distributed network of servers that cache and serve content from locations closer to end users. When a user requests content, the CDN routes the request to the nearest edge server rather than the origin server, dramatically reducing latency and improving load times. CDNs also provide benefits like DDoS protection, SSL/TLS termination at the edge, automatic failover, and reduced bandwidth costs on origin servers. Popular CDNs like Cloudflare, Akamai, and AWS CloudFront can reduce page load times by 50% or more for users far from the origin server.

Q: How does packet routing work across the internet?
A: Packet routing involves forwarding data packets from source to destination through multiple intermediate routers using routing tables and protocols. Each router examines the destination IP address in the packet header and consults its routing table to determine the next hop. Routing protocols like BGP (Border Gateway Protocol) for inter-domain routing and OSPF (Open Shortest Path First) for intra-domain routing continuously update these tables based on network topology and conditions. Packets may take different paths through the network, and the destination host reassembles them in correct order using sequence numbers.

Q: What is the purpose of HTTP status codes and what do the different categories represent?
A: HTTP status codes are three-digit responses that indicate the result of an HTTP request, helping clients understand what happened with their request. The 1xx codes are informational responses, 2xx indicate success (200 OK, 201 Created), 3xx are redirection codes (301 Moved Permanently, 304 Not Modified), 4xx represent client errors (400 Bad Request, 404 Not Found, 403 Forbidden), and 5xx indicate server errors (500 Internal Server Error, 503 Service Unavailable). Understanding these codes is essential for debugging web applications, implementing proper error handling, and building robust API clients.

Q: How do WebSockets differ from traditional HTTP and what are their use cases?
A: WebSockets provide full-duplex, bidirectional communication over a single TCP connection, unlike HTTP which is request-response based and requires a new connection for each exchange. After an initial HTTP handshake that upgrades the connection, WebSockets maintain a persistent connection allowing both client and server to send messages at any time without the overhead of HTTP headers. This makes WebSockets ideal for real-time applications like chat applications, live sports updates, collaborative editing tools, multiplayer games, and financial trading platforms where low latency and server-push capabilities are essential.

Q: What is the OSI model and why is it important for understanding networking?
A: The OSI (Open Systems Interconnection) model is a conceptual framework that standardizes network communication into seven layers: Physical, Data Link, Network, Transport, Session, Presentation, and Application. Each layer has specific responsibilities and communicates only with adjacent layers, promoting modularity and interoperability between different network technologies. Understanding the OSI model helps network engineers troubleshoot issues by isolating problems to specific layers, design network architectures, and understand how protocols like Ethernet (Layer 2), IP (Layer 3), TCP/UDP (Layer 4), and HTTP (Layer 7) interact to enable end-to-end communication.

Q: How do firewalls protect networks and what are the different types?
A: Firewalls are security devices that monitor and filter network traffic based on predetermined security rules, acting as barriers between trusted internal networks and untrusted external networks. Packet-filtering firewalls inspect individual packets against rules based on IP addresses, ports, and protocols. Stateful firewalls track connection states and can make more intelligent decisions based on traffic patterns. Application-layer firewalls (WAFs) inspect traffic at the application level to detect attacks like SQL injection and XSS. Next-generation firewalls combine traditional filtering with intrusion prevention, deep packet inspection, and application awareness for comprehensive protection.

Q: What is NAT (Network Address Translation) and why is it essential for modern networking?
A: NAT is a technique that allows multiple devices on a private network to share a single public IP address when accessing the internet. The NAT device (typically a router) maintains a translation table that maps internal private IP addresses and ports to the external public IP address, rewriting packet headers as traffic flows through. NAT is essential because it conserves the limited IPv4 address space, provides a basic security layer by hiding internal network structure, and enables organizations to use private IP ranges (10.x.x.x, 192.168.x.x, 172.16-31.x.x) internally while maintaining internet connectivity.

Q: How does HTTP/2 improve upon HTTP/1.1?
A: HTTP/2 introduces several significant improvements over HTTP/1.1 to enhance web performance. It uses binary framing instead of text-based protocols, enabling more efficient parsing and reduced errors. Multiplexing allows multiple requests and responses to be sent simultaneously over a single connection, eliminating the head-of-line blocking problem. Header compression using HPACK reduces overhead from repetitive headers. Server push enables servers to proactively send resources before the client requests them. These improvements can reduce page load times by 15-50% and are particularly beneficial for resource-heavy modern web applications.

Q: What is the difference between symmetric and asymmetric encryption in network security?
A: Symmetric encryption uses the same key for both encryption and decryption, making it fast and efficient for encrypting large amounts of data, with algorithms like AES being commonly used. Asymmetric encryption uses a public-private key pair where data encrypted with one key can only be decrypted by the other, enabling secure key exchange and digital signatures but at higher computational cost. In practice, TLS combines both: asymmetric encryption (RSA or ECDHE) securely exchanges a symmetric session key during the handshake, then symmetric encryption (AES) handles the bulk data transfer for optimal security and performance.

Q: What is DHCP and how does it simplify network administration?
A: DHCP (Dynamic Host Configuration Protocol) automatically assigns IP addresses and network configuration parameters to devices joining a network. When a device connects, it broadcasts a DHCP discover message, receives offers from DHCP servers, requests a configuration, and receives an acknowledgment with an IP address, subnet mask, default gateway, and DNS servers. This eliminates manual IP configuration, prevents address conflicts, enables efficient address utilization through leasing, and simplifies network administration especially in environments with many devices or frequent changes. DHCP servers can also reserve specific addresses for particular devices using MAC address binding.

Q: How do VPNs work and what security benefits do they provide?
A: VPNs (Virtual Private Networks) create encrypted tunnels over public networks, allowing secure communication as if devices were on the same private network. The VPN client encapsulates outgoing traffic in encrypted packets, sends them to a VPN server which decrypts and forwards them to the destination, with return traffic following the reverse path. This provides several security benefits: encryption protects data from eavesdropping on untrusted networks, IP masking hides the user's actual location and IP address, and remote access VPNs enable secure connections to corporate networks from anywhere. Common VPN protocols include OpenVPN, WireGuard, IPsec, and L2TP.
