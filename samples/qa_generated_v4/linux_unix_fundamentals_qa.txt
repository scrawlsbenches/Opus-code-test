Q: What do the three permission groups (owner, group, other) in Unix file permissions represent, and how do you interpret a permission string like -rwxr-xr--?
A: The three permission groups control access for different users: owner is the file creator, group includes users in the file's assigned group, and other applies to everyone else. The permission string -rwxr-xr-- indicates a regular file where the owner has read, write, and execute permissions (rwx), the group has read and execute but not write (r-x), and others have only read access (r--). The leading dash indicates a regular file, while 'd' would indicate a directory.

Q: How do you use the chmod command to set permissions numerically, and what do the octal values 755 and 644 represent?
A: The chmod command uses octal notation where each digit represents permissions for owner, group, and other respectively, with read=4, write=2, and execute=1 summed together. The value 755 grants the owner full permissions (7=4+2+1), while group and others get read and execute (5=4+1), making it ideal for executable scripts. The value 644 gives the owner read and write (6=4+2) and everyone else read-only (4), which is standard for regular files that should not be executable.

Q: What is the difference between a process running in the foreground versus the background, and how do you manage this using job control?
A: A foreground process occupies the terminal and receives keyboard input directly, while a background process runs independently, freeing the terminal for other commands. You can start a process in the background by appending an ampersand (command &), or move a running process to the background with Ctrl+Z to suspend it followed by the 'bg' command. The 'fg' command brings a background job to the foreground, and 'jobs' lists all jobs associated with the current shell session.

Q: What is the purpose of the shebang (#!/bin/bash) at the beginning of shell scripts, and what happens if it's omitted?
A: The shebang tells the operating system which interpreter should execute the script, ensuring consistent behavior regardless of the user's default shell. When you run a script directly (./script.sh), the kernel reads the shebang and invokes the specified interpreter with the script as its argument. If omitted, the script runs under the current shell, which may cause syntax errors or unexpected behavior if the script uses features specific to a different shell like bash or zsh.

Q: How does systemd manage services differently from the older SysVinit system, and what are the key systemctl commands for service management?
A: Systemd uses unit files to define services declaratively, supports parallel service startup for faster boot times, and provides dependency management between services. Key commands include 'systemctl start/stop/restart service' for immediate control, 'systemctl enable/disable service' to manage automatic startup at boot, and 'systemctl status service' to view current state and recent logs. Systemd also offers 'journalctl -u service' for accessing comprehensive logs and 'systemctl daemon-reload' to apply changes to unit files.

Q: How do you create a cron job that runs every weekday at 3:30 AM, and what do the five time fields in a crontab entry represent?
A: The five cron time fields are: minute (0-59), hour (0-23), day of month (1-31), month (1-12), and day of week (0-7, where 0 and 7 are Sunday). To run at 3:30 AM on weekdays, the entry would be '30 3 * * 1-5 /path/to/command', where 30 is the minute, 3 is the hour, asterisks mean any day/month, and 1-5 specifies Monday through Friday. Use 'crontab -e' to edit your personal crontab and 'crontab -l' to list existing entries.

Q: What are Unix signals, and how do SIGTERM, SIGKILL, and SIGHUP differ in their behavior and use cases?
A: Signals are software interrupts sent to processes to communicate events or requests, with each signal having a default action that processes can often override. SIGTERM (15) politely requests termination and can be caught by programs to perform cleanup, while SIGKILL (9) forcefully terminates immediately and cannot be caught or ignored. SIGHUP (1) traditionally indicated a terminal hangup but is now commonly used to request that daemons reload their configuration files without fully restarting.

Q: How do pipes and redirection work in Unix, and what is the difference between > and >> for output redirection?
A: Pipes (|) connect the standard output of one command to the standard input of another, enabling powerful command chaining like 'cat file | grep pattern | sort'. Output redirection with > writes stdout to a file, overwriting any existing content, while >> appends to the file preserving existing content. Input redirection with < reads stdin from a file, and 2> redirects stderr separately, with 2>&1 combining stderr into stdout for unified output handling.

Q: What is the difference between environment variables and shell variables, and how do you make a variable available to child processes?
A: Shell variables exist only within the current shell session and are not inherited by commands or scripts you run, while environment variables are exported to child processes. To create an environment variable, use 'export VAR=value' or 'export VAR' after setting it, making it available to all subsequently launched programs. Common environment variables include PATH (command search directories), HOME (user's home directory), and LANG (locale settings), viewable with 'env' or 'printenv'.

Q: How do package managers like apt and yum/dnf differ, and what are the essential commands for installing, updating, and removing packages?
A: Apt is used on Debian-based systems (Ubuntu, Debian) while yum/dnf serves Red Hat-based systems (RHEL, Fedora, CentOS), each with different repository formats and dependency resolution algorithms. For apt: 'apt update' refreshes package lists, 'apt install package' installs, 'apt remove package' uninstalls, and 'apt upgrade' updates all packages. For dnf: 'dnf check-update' shows available updates, 'dnf install package' installs, 'dnf remove package' uninstalls, and 'dnf upgrade' performs system-wide updates.

Q: How does SSH key-based authentication work, and what are the steps to set it up between a client and server?
A: SSH key authentication uses asymmetric cryptography where you generate a private key (kept secret on your machine) and a public key (placed on servers you want to access). Generate a key pair with 'ssh-keygen -t ed25519', then copy the public key to the server using 'ssh-copy-id user@host' or manually appending it to ~/.ssh/authorized_keys. When connecting, the server challenges with data encrypted using your public key, and only your private key can decrypt it, proving your identity without transmitting passwords.

Q: What are the key directories in the Filesystem Hierarchy Standard (FHS), and what types of files belong in /etc, /var, /usr, and /tmp?
A: The FHS standardizes Unix directory structure for consistency across distributions and applications. /etc contains system-wide configuration files like /etc/passwd and /etc/ssh/sshd_config, while /var holds variable data that changes during operation such as logs (/var/log), mail spools, and databases. /usr stores user programs, libraries, and documentation in a read-only hierarchy (/usr/bin, /usr/lib, /usr/share), and /tmp provides temporary file storage that may be cleared on reboot.

Q: How do you use grep to search for patterns in files, and what do the commonly used flags -i, -r, -v, and -E enable?
A: Grep searches files for lines matching a pattern and outputs those lines, making it essential for log analysis and code searching. The -i flag enables case-insensitive matching, -r (or -R) searches recursively through directories, -v inverts the match to show non-matching lines, and -E enables extended regular expressions for patterns like 'error|warning'. Combining flags like 'grep -rni "pattern" /path' performs a recursive, case-insensitive search with line numbers, invaluable for debugging and exploration.

Q: What is awk used for, and how would you extract and sum a specific column from a CSV or space-delimited file?
A: Awk is a pattern-scanning and text-processing language that excels at column-based data manipulation and reporting. It automatically splits each line into fields ($1, $2, etc.) using whitespace as the default delimiter, changeable with -F. To sum the third column of a file: 'awk '{sum += $3} END {print sum}' file', where the main block runs for each line and END executes after all input is processed, outputting the accumulated total.

Q: How does sed perform stream editing, and what is the syntax for find-and-replace operations across files?
A: Sed processes text line by line, applying editing commands without loading entire files into memory, making it efficient for large files. The substitution syntax 's/pattern/replacement/flags' replaces text, where 'g' flag replaces all occurrences per line instead of just the first. To edit files in-place, use 'sed -i 's/old/new/g' file' (or 'sed -i '' on macOS), and for complex patterns, use extended regex with -E, such as 'sed -E 's/[0-9]+/NUM/g'' to replace all numbers with NUM.
