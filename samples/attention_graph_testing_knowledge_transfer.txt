BUG 1: evaluate() Missing vocab_projection Support
----------------------------------------------------------------------
Location: cortical/experiments/kernel.py:329-364
Severity: HIGH

Problem:
  The evaluate() method did not apply vocab_projection to outputs before
  computing loss, while train_step() did. This caused inconsistent loss
  computation between training and evaluation when using vocabulary
  projection (e.g., for language modeling).

Fix:
  Added vocab_projection support to evaluate():

    # Apply vocab projection if present (consistent with train_step)
    if self.vocab_projection is not None:
        projected = self.vocab_projection.forward(outputs, apply_softmax=False)
    else:
        projected = outputs

Test: test_evaluate_with_vocab_projection()

----------------------------------------------------------------------

BUG 2: Global Random Seed Pollution
----------------------------------------------------------------------
Location: cortical/graph/attention.py:1133-1135
Severity: MEDIUM

Problem:
  AttentionGraph used np.random.seed(seed) which sets the GLOBAL numpy
  random state. This affected all numpy random operations in the entire
  program, causing interference when multiple graphs were created or when
  other code also used numpy random.

Fix:
  Replaced with local random generator:

    # Use local random generator instead of global np.random.seed()
    self._rng = np.random.default_rng(seed)

  Updated all random operations in AttentionGraph and AttentionLayer to
  use the local generator (self._rng.standard_normal(), self._rng.binomial()).

Tests:
  - test_local_rng_does_not_affect_global_state()
  - test_same_seed_produces_same_embeddings()
  - test_different_seeds_produce_different_embeddings()

----------------------------------------------------------------------

BUG 3: Silent Zero Fallback for Missing Nodes
----------------------------------------------------------------------
Location: cortical/graph/attention.py:782-798
Severity: LOW (but masks bugs)

Problem:
  When an edge referenced a non-existent node, the code silently used
  zeros instead of raising an error or warning. This could mask bugs in
  graph construction.

Fix:
  Added warnings when nodes are missing:

    if source_node is None:
        warnings.warn(
            f"Edge references non-existent node '{source_id}'. "
            f"Using zeros. This may indicate a bug in graph construction.",
            UserWarning,
            stacklevel=3,
        )

Test: test_warning_on_missing_source_node()

----------------------------------------------------------------------

BUG 4: Missing Self-Attention in Causal Graphs
----------------------------------------------------------------------
Location: cortical/graph/attention.py:1461-1506
Severity: LOW (design decision, but different from standard transformers)

Problem:
  The create_causal_attention_graph() function didn't allow positions to
  attend to themselves. In standard transformers, self-attention IS allowed
  (the diagonal of the attention matrix is not masked).

Fix:
  Added include_self parameter:

    def create_causal_attention_graph(
        seq_len: int,
        embedding_dim: int = 64,
        include_self: bool = False,  # NEW PARAMETER
        **kwargs,
    ) -> AttentionGraph:

  When include_self=True, each position can attend to itself.

Tests:
  - test_include_self_false_no_self_edges()
  - test_include_self_true_creates_self_edges()
  - test_include_self_position_zero_can_attend()
  - test_include_self_attention_weights_include_self()

1. Deterministic Testing with Seeds
----------------------------------------------------------------------
Problem: Random initialization makes tests non-deterministic
Solution: Use explicit seeds for reproducibility

    np.random.seed(123)
    graph = create_causal_attention_graph(seq_len=4, embedding_dim=8, seed=123)

2. Pre-computed Expected Values
----------------------------------------------------------------------
Problem: Hard to verify computed values are correct
Solution: Compute expected values before the operation being tested

    # Get output BEFORE training step to compute expected loss
    outputs_before = graph.forward(num_layers=1)
    output_at_pos3 = outputs_before["pos_3"]
    expected_loss = np.mean(output_at_pos3 ** 2)  # MSE against zeros

    metrics = kernel.train_step(targets, num_layers=1)

    assert abs(metrics.loss - expected_loss) < 1e-10

================================================================================
ARCHITECTURE INSIGHTS
================================================================================

AttentionGraph Design Decisions:
1. Graph edges define attention mask, not attention weights
   - Edges encode structural priors (who can attend to whom)
   - Attention weights are computed dynamically based on content

2. Single-head attention first, designed for multi-head
   - Clean abstractions that extend to multi-head
   - Multi-head implemented via reshaping

3. Store attention weights for backward pass
   - Gradient through softmax requires knowing forward weights
   - Memory vs compute tradeoff (storing is clearer)

ExperimentKernel Design Decisions:
1. Protocol-based interface (TrainableGraphProtocol)
   - Works with any graph implementing the protocol
   - Enables swapping AttentionGraph for TrainableGraph

2. Profiling as optional feature
   - Minimal overhead when disabled
   - Context managers for clean timing

3. Position encoding and vocab projection as optional modules
   - Gradient flow properly handled
   - Parameters included in gradient norm computation
